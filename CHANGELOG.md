# Changelog

All notable changes to CRCForge are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow
[Semantic Versioning](https://semver.org/).

## [1.1.1] - 2026-10-18

### Added

- `crcforge help <command>`.
- Algorithm names work without separators (`crc16modbus`).

### Changed

- New help screens and clearer error messages.
- Results are shown as tables, `calc --all` is grouped by width.
- New banner.
- `brute --poly` tries 0 and all-ones for init/xorout when they are not given.
- `solve --frames` shows only the most likely layout.

### Fixed

- `brute --limit` could hide a catalog match.
- Crashes on an oversized `verify` checksum and on directories passed as files.

## [1.1.0] - 2026-10-18

### Added

- **`solve` command**: identifies the algorithm behind several data/checksum samples. Two or more samples of the same length give the polynomial directly via a GCD over GF(2), for any width (32- and 64-bit included). init and xorout come from a linear system. Catalog CRCs and sum/XOR layouts are checked too, and ambiguous or equivalent parameter sets are explained. When a catalog algorithm already fits, other fits are summarized in one line and the slow polynomial scan is skipped; `--all-solutions` lists everything.
- **Frame analysis** (`solve --frames`): finds the checksum's width, position (`--crc-at`), byte order (`--crc-endian`) and skipped header bytes (`--skip`) inside captured frames. Samples can also come from a file (`--samples-file`).
- **`forge` command**: inserts (by default appends) or overwrites bytes so the data produces a target CRC or sum/XOR checksum. `-o` writes the result to a file.
- **`verify` command**: checks a data/checksum pair, or a frame with an embedded checksum (`--frame`).
- **`records` command**: validates every record of an Intel HEX or Motorola S-record file (checksums, lengths, structure, address range).
- **`codegen` command**: generates table-driven CRC code in C, Python or Rust, for built-in or custom parameters.
- **`info` command**: an algorithm's parameters, aliases, check value, residue, RevEng spec and reference link.
- **Full RevEng catalogue**: all 113 CRC definitions (up from 55), generated by `scripts/sync_reveng_catalog.py` and validated against their check values *and* residues. RevEng's canonical names and aliases are accepted.
- **Checksum families** (issue #1): one's complement (RFC 1071 end-around carry and the S-record "no carry" form), two's complement (Intel HEX, Modbus LRC), plain sums, XOR/BCC, Fletcher-16/32/64, Adler-32, BSD and SysV sums. The catalog now has 134 algorithms.
- **Custom sum checksums** in `calc`, `verify` and `forge` (`--sum`, `--word-size`, `--endian`, `--carry`, `--complement`).
- `calc --all` calculates every catalog algorithm (filter with `--width` and `--family`).
- `--json` and `-q/--quiet` on every command, before or after the command name.
- `list --family` and `list --search`.
- Input from stdin (`-`), and `--offset`, `--length` and `--exclude-tail` to select part of the data.
- `brute --jobs`: large custom searches use every CPU core automatically.
- Live progress with an ETA on stderr. Ctrl+C keeps the partial results.
- A public Python API: `crcforge.calculate`, `find`, `solve`, `forge`, `list_algorithms`, `check_records`.
- Documentation site (MkDocs), CI on Linux, Windows and macOS for Python 3.10–3.14, and a release workflow with PyPI trusted publishing.

### Changed

- **The CRC engine is much faster**: table-driven, with `zlib`/`binascii` fast paths. CRC-32 over 1 MB went from 1.9 s to about 1 ms; other CRCs are about 15 times faster.
- **Custom `brute` searches solve xorout (or init) directly** instead of scanning it, so searches that took years now take seconds. With one sample and both init and xorout free, the search is limited to the conventional values 0 and all-ones, with an explanation. CRCForge also warns when the expected number of coincidental matches is high. `--max-combinations` now counts CRC evaluations; its default is 50,000,000.
- Byte-order modes that produce the same bytes as an earlier mode (for example `reverse` and `swap32` on 4 bytes) are scanned once and reported as skipped.
- Errors now exit with code 2 (1 still means "no match" or "invalid"), go to stderr, and come with hints, including "did you mean" suggestions for algorithm names.
- `list` prints `width=..., poly=..., init=..., refin=..., refout=..., xorout=...` in RevEng order with lowercase booleans.
- Python 3.10 or newer is required (3.9 reached end of life in October 2025).

### Fixed

- **init now uses RevEng notation for reflected CRCs.** CRCForge 1.0 treated `--init` as already reflected when `--refin true`, so parameters copied from RevEng gave wrong results whenever init was not a bit palindrome. For example, CRC-16/TMS37157 with RevEng's init `0x89EC` gave `0xD3CA` instead of `0x26B1`. Built-in algorithms are unaffected except for the internal value of `crc-16-tms37157`.
- Width inference from decimal checksums: `19255` (`0x4B37`) is now 16 bits, not 15.
- Plain text that starts with `0x` (for example `0xygen`) now gives a hint to use `--as-text`, which is no longer hidden from `--help`.
- A plain-text payload that names an existing file now prints a note suggesting `--as-file`.
- `python crcforge.py` and `python -m crcforge` in a source checkout no longer crash when CRCForge is also installed (for example with `pip install -e .`), and `import crcforge` in the checkout root now gives the package. The `crcforge.py` script used to shadow the package.

### Removed

- The built `dist/` artifacts are no longer committed to the repository.

## [1.0.0] - 2026-03-04

Initial release: CRC calculation, catalog matching (`find`, `brute`), custom parameter brute force, byte-order transforms and checksum byte-swap detection, with 55 RevEng CRC definitions.
